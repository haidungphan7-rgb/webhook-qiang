# 部署与交付指南

## 1. 交付产物是什么

### 形态一：单个二进制（推荐）

`go build` 出来就**一个文件**，前端已经 `go:embed` 进去了。

| 平台 | 文件 | 体积 |
|---|---|---|
| Windows x64 | `webhook-zq.exe` | ≈ 15.7 MB |
| Linux x64 | `webhook-zq-linux-amd64` | ≈ 15.3 MB |
| macOS ARM64 | `webhook-zq-darwin-arm64` | ≈ 14.8 MB |

构建命令（`-trimpath -ldflags '-s -w'` 去掉调试信息与路径，体积约减 30%）：

```bash
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 \
  go build -trimpath -ldflags '-s -w' -o bin/webhook-zq ./cmd/webhook-tester
```

**已实测**：把 `webhook-zq.exe` 单独复制到一个空目录（没有 `web/`、没有 `node_modules`），`start` 起来后
`GET /` 返回 200 且能加载 `assets/*.js`——**运行期不需要 Node、不需要前端源码、不需要静态文件目录**。

### 形态二：Docker 镜像

`Dockerfile` 是三阶段（node → golang → alpine），镜像里同样只有二进制 + CA 证书，非 root（uid 10001），带 `HEALTHCHECK`。

### 形态三：源码仓库

`git clone` → `go build`，无代码生成步骤（`oapi-codegen` 已移除）。合合使用者自己验。

## 2. 运行时依赖

**只有一个外部依赖：PostgreSQL ≥ 14。**

| 项 | 说明 |
|---|---|
| PostgreSQL | 唯一存储。Redis / MQ / 对象存储一概不需要 |
| 扩展 `pg_trgm` | 关键字搜索的 GIN 索引 |
| 扩展 `pgcrypto` | `gen_random_uuid()` |

> 两个扩展都不是 trusted 扩展（PG 13+）。若应用账号不是数据库属主，先让 DBA 执行：
> ```sql
> CREATE EXTENSION IF NOT EXISTS pg_trgm;
> CREATE EXTENSION IF NOT EXISTS pgcrypto;
> ```

**不需要**：Node.js（只在构建前端时用）、Redis、消息队列、对象存储、Nginx（可选）。

## 3. 部署方式

### 0. 新机器最快路径：启动器

```powershell
pwsh ./scripts/setup.ps1          # 交互：本机 / Docker / 只检查环境
```

或双击 **`启动.bat`**。它会：

1. **检查** go / node / psql / docker；没装的直接给出 `winget install` 命令
2. **建库**（`webhook_rd`），迁移由服务启动时自动跑
3. **构建**后端（或复用 `bin/webhook-zq.exe`）；前端若 `web/dist` 还是占位页则自动 `npm ci && npm run build`
4. **启动**并打印下一步命令

已知的两个环境坑，脚本都处理了：

- **psql 常常不在 PATH**（PostgreSQL 安装器默认不加 `bin`），脚本会去 `C:\Program Files\PostgreSQL\*\bin` 找，并把该目录临时加入 PATH（`createdb` 也就跟着可用了）
- **psql 的 `-c` 等选项必须写在 `-d` 之前**，否则被静默忽略、返回空

`psql` / `createdb` 在无控制台时会等在 stdin 上，所以**从终端运行或双击 bat**；完全无头场景请用 `-NoStart` 再自行启动二进制。每步都记进 `logs/setup.log`。

### A. Docker Compose（最快）

```bash
docker compose up -d         # 内含 PostgreSQL 16
```

默认**不放行本地重放**：`docker-compose.yml` 里 `REPLAY_ALLOW_HOSTS` / `REPLAY_ALLOW_PRIVATE` 是注释掉的——
这是安全默认值。要演示本机重放再取消注释。

### B. Linux systemd（生产推荐）

```bash
# 1) 落地二进制
sudo install -m 0755 webhook-zq-linux-amd64 /usr/local/bin/webhook-zq

# 2) 建库（迁移只建表，不建库）
sudo -u postgres createdb webhook_rd
sudo -u postgres psql -d webhook_rd -c "CREATE EXTENSION IF NOT EXISTS pg_trgm; CREATE EXTENSION IF NOT EXISTS pgcrypto;"

# 3) 只跑迁移（不启服务），确认 schema 到位
webhook-zq migrate --database-url "$DATABASE_URL"
webhook-zq migrate --check --database-url "$DATABASE_URL"   # 退出码 0 表示版本一致
```

`/etc/systemd/system/webhook-zq.service`：

```ini
[Unit]
Description=Webhook debug and replay platform
After=network-online.target postgresql.service
Wants=network-online.target

[Service]
Type=simple
User=webhook-zq
Group=webhook-zq
Environment=DATABASE_URL=postgres://webhook:CHANGE_ME@127.0.0.1:5432/webhook_rd?sslmode=require
Environment=PUBLIC_URL_ROOT=https://wh.example.com
Environment=ENCRYPT_KEY=REPLACE_WITH_BASE64_32_BYTES
Environment=AUTH_KEYS=alice:keyA,bob:keyB
Environment=REPLAY_TIMEOUT=5s
Environment=REPLAY_RATE_LIMIT=30
Environment=LOG_LEVEL=info
Environment=LOG_FORMAT=json
ExecStart=/usr/local/bin/webhook-zq start --port 8080
Restart=on-failure
RestartSec=3

# 加固：密钥走 Environment 而不是命令行，避免出现在 ps 输出里
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ProtectHome=true
ReadWritePaths=/var/log/webhook-zq

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now webhook-zq
curl -fsS http://127.0.0.1:8080/healthz     # 探针，含数据库连通性
```

### C. Windows

用 `wh.exe start` 直接跑即可；要做成服务用 NSSM 或「计划任务（计算机启动时）」。
密钥同样建议放环境变量而不是命令行。

## 4. 反向代理（建议放一层）

用 Nginx / Caddy 终止 TLS，并做两件应用本身没做的事：

```nginx
# 收件入口是公开的，必须限流 —— 应用侧没有对 /hooks 做限流
limit_req_zone $binary_remote_addr zone=hook:10m rate=10r/s;

location /hooks/ {
    limit_req zone=hook burst=20 nodelay;
    proxy_pass http://127.0.0.1:8080;
}

location / {
    proxy_pass http://127.0.0.1:8080;
}

# WebSocket 实时推送需要这两行
location /api/v1/inboxes/ {
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 60s;
}
```

设置 `--public-url-root https://wh.example.com`，否则导出的 cURL 和页面上的接收地址是相对路径
（这是刻意的：服务不假装知道自己的公网域名）。

## 5. 上线前清单

| 项 | 必做 | 说明 |
|---|---|---|
| `DATABASE_URL` 用**专用账号** | ✅ | 不要给属主权限；提前装好两个扩展 |
| `sslmode` | ✅ | 跨机用 `require`，别用 `disable` |
| `ENCRYPT_KEY` | 强烈建议 | 32 字节 base64。**丢了无法解密已存敏感头**——先备份它 |
| `AUTH_TOKEN` 或 `AUTH_KEYS` | ✅（多人时） | 否则任何人都能看所有收件箱、导出敏感头 |
| **不要**开 `REPLAY_ALLOW_PRIVATE` | ✅ | 那是唯一 SSRF 闸，只在受控演示环境开 |
| `PUBLIC_URL_ROOT` | 建议 | 影响导出的 cURL 与页面展示的接收地址 |
| `/hooks/` 限流 | ✅ | 应用侧未限流，交给反代 |
| 备份 | ✅ | `pg_dump`；`ENCRYPT_KEY` 要跟着一起备份 |
| 保留策略 | 建议 | `--retention-max-events` / `--retention-max-days`，默认每箱 500 条 / 30 天 |

### 密钥生成

```powershell
# 32 字节主密钥（敏感头加密用）
$bytes = New-Object byte[] 32
[System.Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($bytes)
[Convert]::ToBase64String($bytes)
```

或者直接用预置脚本，它会生成并打印：`pwsh ./scripts/start-secure.ps1`

## 6. 升级与回滚

迁移是**向前累加、事务化、幂等**的（`schema_migrations` 表记录版本）：

```bash
systemctl stop webhook-zq
install -m 0755 webhook-zq-new /usr/local/bin/webhook-zq
systemctl start webhook-zq          # 启动时自动应用新迁移
```

先 `webhook-zq migrate --check` 可以只检查不启动。

回滚：换回旧二进制即可——**但如果新版本加过迁移，旧版本不认新列**。所以：
1. 升级前 `pg_dump`；
2. 迁移只做「加列、加索引」这类可逆变更（本项目一直是这么做的，`body_text` 就是这么加的）。

> 已知边界：迁移没有 advisory lock，多副本同时启动理论上会并发跑迁移。启动顺序串行化即可避开。

## 7. 观测

| 端点 | 用途 |
|---|---|
| `GET /healthz` | 存活 + 数据库连通性（Docker HEALTHCHECK 接的就是它） |
| `GET /api/v1/settings` | 当前生效的全部运行参数——排障先看这里 |
| 日志 | `--log-format json` 结构化；每个请求带 `request_id` |
| 敏感头解密 | 每次 `?reveal=1` 都会记审计日志（需要开启了访问控制） |

排障第一步永远是看 `/api/v1/settings`：它回答"这台实例现在到底是怎么配的"。

## 8. 已知不合合直接上生产的点

如实列出（README §7 也有）：

1. 实时推送是**单实例内存 pub/sub**，多副本要换成 Redis 或 PG LISTEN/NOTIFY（改 `internal/pubsub` 一处）。
2. 重放限流是**进程内固定窗口**，多副本会放大 N 倍；生产要放到网关层。
3. 迁移没有 advisory lock。
4. `/hooks/{token}` 未限流，必须靠反代。
5. 租户只来自 API 密钥，没有用户/角色体系，密钥轮换需要重启。
6. 不是完美的 SSRF 方案：不限制端口、不防"公网主机当跳板"、不做 IP pinning。
